### Corrections to the previous version of this README

The previous README described an "operational MVP pilot trained & verified" crack detector
with precision 0.642 and recall 0.667. Those numbers were measured on 8 images against boxes
generated by an OpenCV heuristic (with a fixed centre box as fallback), not against human
annotations. They describe agreement with the heuristic, not crack detection. The demo
"detections" cover most of each image. Details: `docs/MODEL_CARD_crack_pilot_v0.md`.

## Scope and principles

* Outputs are **candidate observations for human review**. Nothing here assesses structural
  safety, material chemistry, groundwater, or repairs.
* The task follows the supervision that exists: image-level labels → classification only;
  boxes → detection; masks → segmentation. Folder names are not labels until reviewed.
* The current data comes from one site (Darbhanga Fort). No result from it may be presented as
  working across India's water heritage (baolis, kunds, tanks, temple tanks …) until those are
  in the evaluation data.

## Workflow — crack detection (run from the repository root)

```bash
# 0. Extract DrabhangaDataset.zip (outer zip contains an inner zip) to data/raw/darbhanga_crack/

# 1. Audit images, labels and duplicates
python3 scripts/vision/audit_dataset.py --data-dir "data/raw/darbhanga_crack/Crack Data-Darbhanga Fort" \
    --out vision/outputs/audit

# 2. Leakage-safe re-split (published split is not used)
python3 scripts/vision/make_detection_splits.py --config vision/configs/detection_pilot.yaml \
    --manifest vision/outputs/audit/manifest.jsonl

# 3. Bounded check, then the full run (CPU, ~13 min/epoch on an Apple M2)
python3 scripts/vision/train_detector.py --config vision/configs/detection_pilot.yaml \
    --epochs 1 --max-train-batches 20 --max-val-images 64 --run-name bounded_check
python3 scripts/vision/train_detector.py --config vision/configs/detection_pilot.yaml --run-name pilot_v1

# 4. Validation, then test exactly once
python3 scripts/vision/evaluate_detector.py --checkpoint vision/outputs/experiments/darbhanga_crack_detection_pilot/pilot_v1/model.pt \
    --config vision/configs/detection_pilot.yaml --split val
python3 scripts/vision/evaluate_detector.py ... --split test

# Tests (not collected by the root pytest config, which only runs tests/)
python3 -m pytest vision/tests -q
```

Torchvision weight downloads: this machine's python.org Python lacks a CA bundle, so the official
COCO/ImageNet weights were fetched with `curl` into `~/.cache/torch/hub/checkpoints/` and their
published SHA-256 prefixes checked (`fasterrcnn_mobilenet_v3_large_fpn-fb6a3cc7.pth`,
`resnet18-f37072fd.pth`). Running `Install Certificates.command` from the Python folder also fixes it.

## Workflow — image-level classifier (folder datasets)

```bash
python3 scripts/vision/make_contact_sheets.py --data-dir <root> --manifest vision/outputs/audit/manifest.jsonl
python3 scripts/vision/make_splits.py --config vision/configs/classification_pilot.yaml --manifest vision/outputs/audit/manifest.jsonl
python3 scripts/vision/train_classifier.py --config vision/configs/classification_pilot.yaml
python3 scripts/vision/evaluate_classifier.py --checkpoint <run_dir>/model.pt --config vision/configs/classification_pilot.yaml --split val
```

`train_classifier.py` refuses to run while labels are unverified. `--allow-unverified-labels`
exists for pipeline smoke tests; such checkpoints are marked `label_status: unverified` and the
predictor attaches a warning to every result.

## Artefact hygiene

Datasets, manifests, run directories and checkpoints live under `vision/outputs/`, `data/raw/`
or outside the repository and are gitignored (`*.pt`, `vision/outputs/*`, `data/raw/*`,
`/DrabhangaDataset.zip`). Manifests store paths relative to the dataset root. The only tracked
weights are the legacy pilot and `models/crack_detector_pilot_v1/model.pt`, each by an explicit
`.gitignore` exception. No dataset images are tracked apart from the seven legacy demo images.
