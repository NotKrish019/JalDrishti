## How it was actually trained

* **Labels were generated by a heuristic, not drawn by people.** `create_crack_pilot.py`
  runs an OpenCV black-hat filter, thresholds it, and boxes the three largest dark contours.
  If no contour passes the area threshold, it writes a fixed box covering the central 40% of
  the image. The model therefore learned to imitate that heuristic.
* **Data:** the first 16 `Damaged_images` and first 16 `Background_images` by filename;
  12 + 12 for training, 4 + 4 for validation. No duplicate or leakage check.
* **Metrics:** the earlier README reports precision 0.642, recall 0.667, mAP50 0.26–0.30 on
  the 8 validation images. Those were measured **against the heuristic boxes**, on 8 images,
  so they say how well the detector reproduces the heuristic, not how well it finds cracks.
  They cannot be reproduced here (dataset and Ultralytics are absent on this machine).
* **Demo outputs:** the boxes in `vision/demo_assets/evaluation_summary.json` cover most of the
  image (e.g. `[0, 0, 767, 767]`, `[1, 0, 768, 765]`), which is not localisation. The "unseen"
  demo images were hand-picked, not a held-out split.

## Intended use (as it stands)

Demonstrating the inference plumbing only. Its boxes must not be presented as crack locations,
and its confidence must not be presented as the probability that a crack exists.

## Recommendation

1. Backend (Swastik): replace this checkpoint with the crack detector `pilot_v1` through
   `vision.inference.DetectionPredictor` (see `INFERENCE_INTERFACE.md` and
   `MODEL_CARD_crack_detector.md`), which was trained on the dataset's published annotation
   boxes (spot-checked, noisy) and evaluated on a leakage-safe held-out split. No backend code was
   changed as part of this work.
2. Re-check the 2026-10-08 pretrained YOLOv8n-seg smoke test (11.73 ms on one image, GTX 1650)
   only as a runtime check; it was never evidence of heritage-specific detection.
